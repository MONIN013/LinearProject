# Feedforward experiment (R2025a)

TwinCATと磁極推定側はプロジェクト内の [`twincat/`](../twincat/NikonMotorProject2025.sln) と `exp00_Commissioning/` に統合済み。
ルートの `setup_project` で共通関数とCopley MATLAB APIをpathへ追加できる。
統合後の実機FFあり・なし試験は [2026-09-07の統合記録](../docs/copley-integration-2026-09-07.md) を参照。
全条件で取得・停止確認は成功したが、非ゼロFFでは2 Aへの飽和があり、係数最適化は未完了。

2026-09-08には統合先TwinCATをビルド・ActivateしてFF実機完走を再確認した。
共通取得関数の終了時 `onCleanup` 警告を修正。計測値と検証範囲は
[2026-09-08の確認記録](../docs/ff-verification-2026-09-08.md) を参照。

## 仮想CSTとの責務分担

`linear_exp_2025a.slx` と `linear_exp_tunable_2025a.slx` は、どちらも
`Target Torque` を1本だけ出力する。実軸1～4の選択、結線交換に伴う磁極参照、
鎖交区間とマージンは `twincat/MotorRuntime` が扱う。
Simulink側に軸別ゲートを追加しない。

## 実行前の確認

1. プロジェクトを開き、`feedforward_experiment.m` の設定・制御器・軌道を確認する。
2. モデルまたはサンプル周期を変更した場合は `setup_tunable.m` を実行し、
   生成した同じ版のモジュールをTwinCATへインストール・Activateする。
   標準の周期は4 kHz (`Ts = 0.00025 s`)。
3. 実験節では `home_to_start(54100000)` で開始位置へ自動復帰してから、
   `obtainMeasurement.m` で接続・計測する。前回のステージング計測は
   `data/archive/` へ退避し、今回の計測と結果は `data/ff/<日時_run>/` に保存する。

生成物は `CodeGen/`、キャッシュは `Cache/` を使用する。
ビルドと取得の両方で同じ保存先を設定するため、MATLABを再起動しても
外部モード用の `*_targ_data_map.m` を解決できる。
生成物を削除した場合は再ビルドが必要。

取得処理は接続完了を待ってからサーボを有効化する。正常終了・例外・中断時は
まず `p_active = 0` / `p_servo = 0`、次にstop、バッファ初期化、disconnectの順で終了する。
通信異常時のMATLAB側cleanupだけを非常停止の代用にしない。

別セッションでモデルを更新した際、既に開いている古いモデルは自動更新されない。
未保存の変更があれば退避し、ディスク上の修正版を開き直してから使用する。

## ソフトウェアHoming

`home_to_start` は現在の絶対エンコーダCountを読み、開始位置54,100,000 countへ
片道の5次軌道で戻す。エンコーダのゼロリセットや原点スイッチ探索は行わない。
速度上限0.2 m/s、加速度上限0.5 m/s²、到達許容差100 µm。
許容差内なら再移動を省略し、FFの0.84 m往復軌道自体は変更しない。
実装は共通の `src/home_to_start.m`。FFの設定節を事前実行する必要はない。
周期・モータ設定・既存の `fbDesign` 制御器を、生成時と同じbase workspaceに
一時設定し、正常終了・例外時とも元の値と参照スコープへ復元する。
呼出元の `Kd`、軌道、FF/ILC係数は呼出し後に保持される。
現在位置と目標が計測済み範囲内、停止・Faultなしを確認してから、既存の仮想CSTと
`src/capture_tunable_trajectory.m` のサーボ制御・cleanupを利用する。
FFの `obtainMeasurement.m` も同じ取得関数を呼ぶ。
結果は呼出元の現在フォルダに関係なくプロジェクトの `data/homing/<日時_run>/Homing_Result.mat`。
これは原点スイッチによる原点確立や独立したハードウェア安全機能の代用ではない。

### FF以外からの使い方

MATLAB Projectを開く（または `src` をpathへ追加する）と、各実験から次を呼べる。

```matlab
[measurement, homing] = home_to_start();          % 54,100,000 countへ
[measurement, homing] = home_to_start(55000000);  % 任意の範囲内Countへ
```

- FF / ILC: 同じtunableモデルを使用する。実験開始・外部モード接続の前に呼ぶ。
  ILCの連続trial実行中には呼ばない。
- SI / FB: legacyモデル配備中のHomingには対応しない。
  共通tunableモジュールをActivateした状態でHomingし、その後SI/FB用モデルを
  Activateして本実験を行う。Homing関数は自動build・Activateを行わない。
- 共通tunableモデルは現在周期・既存 `fbDesign` と同じ生成構造で配備済みが前提。
  任意のモデル・制御器への自動切替や再ビルドは行わない。

2026-09-07、起動済みVS2019のCopleyTestで通常CST指令リンク2本を修正して
0.0.0.36をActivateし、Run復帰を確認した。同版で共通HomingをSIフォルダから
54,200,000 countへ、ILCフォルダから54,100,000 countへ実行し、それぞれ
到達誤差−34.5 µm / +26.2 µm、7,360点 / 7,358点で欠落なし。
呼出元とモデルworkspaceの制御器・軌道・変数有無、現在フォルダの復元を確認。
終了後は全軸トルク指令0・速度0・`p_active=p_servo=0`。
結果は `data/homing/20260907_153033_Homing_Result_2026-09-07_3/Homing_Result_2026-09-07_3.mat` と `_4.mat`。

## 高速な実験反復

同じモデル・周期・固定バッファ構成で軌道やFF係数だけを調整するときは、
`setup_tunable.m` のビルド節を飛ばして生成済みモジュールを再利用し、
軌道生成 → `obtainMeasurement.m` → 結果確認を繰り返す。毎回の全件テストは不要。
実験スクリプトを「すべて実行」するとビルド節も通るため、反復時は必要な節だけ実行する。

コードを変えた場合のみ、対応するテストを1回実行する。
停止・電流上限・通信異常時の保護と、計測欠落・追従・終了後の無励磁の確認は維持する。
制御器・プラントを変えた場合は、その組合せの安定性・感度も確認する。

## 実験データの保存

FF取得開始時に `data/ff/<日時_run>/` を作成する。結果MATは従来の
basename（例: `V1.000_notSpecial_Result.mat`）を保ち、TwinCATの分割計測は
`raw/`、この実行で作成した図は `figures/` にまとめる。比較プロットは
`data/ff/` と `data/ilc/` 以下のrunを横断して読む。

FFテストから、現行の `fbDesign` を使わない旧PID係数の固定値テストと、
ソース文字列を照合するだけのスクリプト契約テストを削除（12件 → 10件）。
モデルの単一トルク出力、無効時のトルク遮断、電流上限、バッファ境界、計測形式のテストは残す。
