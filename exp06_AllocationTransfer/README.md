# 電流配分を変えたFFの比較

入口は `allocation_transfer_experiment.m`。exp03〜05と同じ、設定・軌道・取得・同定・比較の順に読む実験スクリプト。
全体実行すると節3・5で実機が動く。節1・2は準備、節4は保存済み教師からの同定だけを行う。

PR [LinearProject #2](https://github.com/MONIN013/LinearProject/pull/2) の条件表と多項式軌道を取り込み、
説明に合わせて移動距離を60 mmに統一した。軸1・2の重なり区間で、開始位置56,100,000 count、
終点56,700,000 count、4 kHz。往路の片道時間・skewを変え、復路は位置を反転した波形を使う。

## 実験

- 学習は `(片道秒, skew) = (2,-2), (3,0), (4,2)` と `beta = -0.1, 0, +0.1` の9条件。
- validationは `(3,0,+0.05), (2.7,1,0), (2.7,1,+0.05)`。
- testは `(3,0,-0.05), (3.3,-1,0), (3.3,-1,-0.05)`。

配分は `w1=1+beta, w2=1-beta*ratio`。`ratio=g1/g2` が正しい場合に名目推力を保つ。
既定のratio=1は仮定で、今回のコード追加では推力定数を実測していない。
両軸の倍率を0.8〜1.2に収める。Simulinkは従来どおり1本の仮想トルクを出し、実軸配分はMotorRuntimeが行う。

教師取得はexp04のILC、取得結果の検査と保存はexp05の `obtainMeasurement.m` を使う。
Q420 Hz、最大80試行、後半8本平均FFの固定8回検証を維持する。
今回の精度目標は全区間・移動中RMS 10 µm、最大誤差100 µm。実測達成値ではなく、冒頭で調整する採用条件。
exp06では固定FFの最後の8回すべてでこの精度とFB比率20%以下を満たし、飽和がないことを採用条件にする。
精度目標を満たす数µmのばらつきに対して、追加でRMS変動5%以内を要求しない。変動量自体は記録する。
9教師はexp05と分けて `data/allocation_transfer/current_teachers.mat` に記録し、再利用時も設定・精度・軸ログを確認する。

適用FF（row7）と実測絶対位置（row8）から、配分別に `g(x), b(x), c(x), alpha(x)` を同定する。
比較条件のbetaへ係数と方向別実測FF範囲を線形補間し、exp05と同じ端部処理・遅延補償で再生する。
betaの外挿はしない。比較はFFなし・beta=0固定マップ・配分に合わせた補間マップの3種類。
beta=0では後者2つの重複取得を省く。validation/testのデータは教師へ追加しない。
完了表示は取得の完了であり、転移による改善は比較表のRMS・最大誤差から判断する。

## MotorRuntimeと軸別ログ

初回は更新した `twincat/NikonMotorProject2025.sln` をビルドし、別途実機へ反映する。
スクリプトはActivateやPLCダウンロードを行わない。古いRuntimeでは新しいログ定義の確認時に停止する。
Simulinkの共通File WriterへPLCの軸別スナップショットを追加した。
保存時の30行のうち、先頭10行は従来どおり。MATLABで読み込むと `measurement` は10行、
軸別データは `measurement_metadata.axisLog` になる。

`GVL_AllocationTransfer` に配分を書き、最後にRequestIdを更新する。PLCは停止中だけ受理し、AckIdとRejectIdを返す。
配分はSimulink側の要求IDと一致する1回のサーボON区間だけ有効で、OFFで通常配分に戻る。
ILCも毎試行設定し直す。Homingとexp01〜05は要求IDを0にして通常配分を使う。
停止・通信保護は既存経路を使い、配分後の各軸指令が2 Aを超えたら停止する。電流を切り詰めて成功扱いにはしない。
追加faultは630（区間・周期・要求ID・通信・元のfault）、631（配分後電流上限）。
停止後に配分の解除要求で追加faultを解除する。元のドライブfaultや通信faultの解除方法は従来どおり。

取得中は各試行の `allocation_log.mat` に、4軸の指令電流・実電流・状態語、仮想電流、絶対位置・速度、fault、周期、要求IDを保存する。
PLCは現在の1周期分（80 byte）だけを公開する。MATLABから設定した軌道の実行区間を、
Simulinkの共通File Writerが4 kHzで記録する。PLC側の履歴バッファ・別途ダウンロードは使わない。
指令・実電流は物理PDOの0.1 A/1000 countをAへ換算する。
PLCの連続サイクルと要求IDを検査し、実際の2軸指令が指定倍率と一致することも確認する。
開始直前のPLC周期が記録されるため、全軸OFF・電流ゼロ・参照ゼロの連続した先頭部分だけは要求ID=0を許容し、点数を残す。
配分開始後のID不一致や、先頭でも通電・非ゼロ参照がある場合は拒否する。
軸ログと従来10行は同じFile Writerの同じ時刻・列に保存する。
PLCとTcCOMの実行順による1周期の入出力遅れは、両者の仮想電流と絶対位置から確認する。
2026-09-21の4 kHz実測では、絶対位置は同じ列で一致し、軸ログの仮想電流は
従来row3を2 mA単位で量子化した値より1周期遅れていた。軸ログ内の配分照合に時刻ずらしは不要。

結果・図は `data/allocation_transfer/<日時_実験名>/`。終了時に軸ログを結果MATへ集約する。
ILCは `history.allocationLog{試行番号}.axisLog`、比較は `allocationLog.axisLog` から参照する。
分割計測と途中保存はローカル退避し、結果MATだけで教師の再利用と軸別解析ができる。

オフライン検証は `tests/test_allocation_transfer.m` と `tests/test_axis_snapshot_logging.m`。
準備節、合成データでの同定・補間、共通記録からの軸ログ換算と欠落検出を確認する。実機性能を証明するものではない。
配分変更後の実測FRFは未取得。名目モデルの推力ゲイン0.8〜1.2では閉ループ安定、感度ピーク最大1.54001を確認した。

2026-09-21: MotorRuntimeと共通TcCOM 0.0.0.40を実機へ反映し、9教師・16比較を完了した。
beta=+0.1では物理軸への指令倍率1.1/0.9、連続した32,001点の記録、終了後の配分解除を確認した。
教師の固定8回RMSは2.50〜3.65 µm、マップ再生のRMSは49.30〜51.00 µmで、同条件のFBより16〜20%改善した。
配分補間の固定マップに対する効果は+1.34〜-0.48%で、一貫した優位性は確認できなかった。
低速・停止でFFをゼロへ戻す付近に誤差が残る。16比較とも欠測・fault・飽和なし、終了後無励磁を確認した。
今回の手法・数値結果・未確認事項は [実機確認結果](../docs/experiments-verification-2026-09-21.md) にまとめた。
